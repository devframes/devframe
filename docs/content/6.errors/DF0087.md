---
title: 'DF0087: Settings Notice Marker Not Written'
description: 'Could not write the settings notice marker "{filepath}"'
---

## Message

> Could not write the settings notice marker "`{filepath}`"

## Cause

Dismissing the one-time shared-scope settings notice writes a marker file into the global settings directory (`<global>/settings/.shared-scope-notice`). The directory could not be created, or the file could not be written, usually because the global storage directory is not writable or the disk is full.

The dismissal itself is not an error: the notice disappears for the current session. The marker only makes it stay gone.

## Fix

Check that the global storage directory is writable and has free space. Until the marker lands, the notice shows again the next time a viewer opens settings.

## Source

- [`packages/devframe/src/node/settings-legacy-notice.ts`](https://github.com/devframes/devframe/blob/main/packages/devframe/src/node/settings-legacy-notice.ts): `dismissLegacySharedSettingsNotice()` reports this when creating the directory or writing the marker fails. The `devframe:settings:legacy-notice-dismiss` RPC calls it.
