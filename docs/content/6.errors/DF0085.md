---
title: 'DF0085: Repeated MCP Prompt Name'
description: 'MCP prompt "{name}" is listed more than once.'
---

## Message

> MCP prompt "`{name}`" is listed more than once.

## Cause

Two entries in the `prompts` list of the MCP route options (or of `createMcpServer` / `createMcpFetchHandler`) have the same `name`. `prompts/get` finds a prompt by its name, so the second one could never be reached. The check runs once, when the MCP route mounts or `createMcpServer` starts, so no request is served with an ambiguous list.

## Example

```ts
initDevframe(myDevframe, {
  mcp: {
    prompts: [
      {
        name: 'review',
        get: () => ({ messages: [] })
      },
      {
        name: 'review',
        get: () => ({ messages: [] })
      }, // same name → DF0085
    ],
  },
})
```

## Fix

Give each prompt its own `name`, or merge the two into one prompt with an argument that picks between them.

## Source

- [`packages/agentic/src/mcp/build-server.ts`](https://github.com/devframes/devframe/blob/main/packages/agentic/src/mcp/build-server.ts): `compilePrompts()` throws this for a repeated name. `createMcpFetchHandler()` (which `mountMcpHttp()` and the MCP route use) and `createMcpServer()` call it once, before they serve any request.
