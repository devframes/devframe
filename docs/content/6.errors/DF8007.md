## Message

> buildHub's base ("`{base}`") is not under its deployBase ("`{deployBase}`"), so the hub itself would be served outside the deploy root.

## Cause

`deployBase` is the URL prefix the whole output tree is served under, and the hub sits inside that tree. A hub `base` outside it describes a second deployment, so the baked URLs and the file layout would disagree.

## Example

```ts
// ✓ Good: the hub base includes the deploy prefix
await buildHub({
  outDir: 'dist/__devtools',
  base: '/ci-build-123456/__devtools/',
  deployBase: '/ci-build-123456/',
})

// ✗ Bad: the hub would be served at the domain root
await buildHub({
  outDir: 'dist/__devtools',
  base: '/__devtools/',
  deployBase: '/ci-build-123456/',
})
```

## Fix

Include the deploy prefix in `base`, or omit `deployBase` when the output is served at the domain root.

## Source

- [`packages/hub/src/node/build.ts`](https://github.com/devframes/devframe/blob/main/packages/hub/src/node/build.ts): `buildHub()` rejects a `base` that does not start with `deployBase`.
