## Message

> "`{id}`" exposes agent tools and MCP defaults to `'auto'`, but the optional peer @modelcontextprotocol/server could not be imported, so no MCP route was mounted: `{reason}`

## Cause

The devframe (or hub) exposes an agent surface - an `agent`-flagged RPC function, or a tool / resource registered on `ctx.agent` - and the `mcp` setting is the `'auto'` default, which mounts the route once that surface exists. The optional peer `@modelcontextprotocol/server` could not be imported, so the tools have nowhere to be served and the route stays unmounted. The warning fires once per instance.

## Example

A definition flags a function for agents but the package that runs it has no MCP SDK installed:

```ts
export const getState = defineRpcFunction({
  name: 'get-state',
  type: 'query',
  jsonSerializable: true,
  agent: { description: 'Read the current state.' }, // agent surface exists
  setup: ctx => ({ handler: () => ctx.cwd }),
})
```

## Fix

- Install the peer next to `devframe` so the `'auto'` default can serve the surface: `npm install @modelcontextprotocol/server`.
- Or set `mcp: false` where you host the tool (`createCac`, `initDevframe`, `initHub`, or `createDevServer`) to keep the route off and silence the warning.

## Source

- [`packages/devframe/src/adapters/_shared.ts`](https://github.com/devframes/devframe/blob/main/packages/devframe/src/adapters/_shared.ts): `loadAutoMcpAdapter()` warns this when the `'auto'` default finds a non-empty agent surface but the peer fails to import; consumed by `initDevframe` and `initHub`.
