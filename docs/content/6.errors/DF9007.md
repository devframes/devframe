## Message

> A browser asked to run `{command}`, but another program reads this terminal key by key, so it cannot show the question. The install was refused.

## Cause

Each install that the panel asks for needs the developer's permission ([DF9005](/errors/DF9005)). Without an `onConfirm` option, `createOnboarding()` asks in the terminal. Here stdin is in raw mode, so another program in the same process reads each key as it is typed. A full-screen CLI does this for its single-key shortcuts. The CLI also captures the log, so the question does not show, and the next key would answer it. The install is refused at once, and the panel tells the user.

The Nuxt CLI (`nuxi dev`) does this in its interactive interface, the default in a terminal of at least 40 by 10 characters.

## Fix

Run the command from the panel in a terminal yourself. If you maintain the host, pass an `onConfirm` function to `createOnboarding()` that asks through the CLI that owns the terminal.

## Source

- [`packages/hub-ui-onboard/src/terminal-confirm.ts`](https://github.com/devframes/devframe/blob/main/packages/hub-ui-onboard/src/terminal-confirm.ts): `confirmInTerminal()` reports this and returns `false` when stdin is a TTY in raw mode.
